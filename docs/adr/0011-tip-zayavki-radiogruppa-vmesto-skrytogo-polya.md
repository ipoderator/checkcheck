# 0011. Тип заявки — радиогруппа, которую JS превращает во вкладки

## Контекст

Обработчик принимает поле `type` (`price` | `partner`). Вкладки «Рассчитать цену» / «Сотрудничество» были кнопками плюс скрытое поле `type=price`. Без JS (ADR 0007) кнопки ничего не делали, и заявка на сотрудничество не могла быть отправлена: известный баг, история 88.

## Решение

Тип заявки — нативная группа радиокнопок `name="type"`, видимая и рабочая без JS. С JS радио скрываются, вместо них показываются прежние вкладки с `role="tab"`, они пишут в ту же группу. Контракт `POST /api/lead.php`, якоря `#price` и `#partner`, селекторы `data-lead-type` и черновик не меняются. Поля только для цены без JS остаются видимыми, сервер сам отбрасывает их для `partner`.

## Почему

- Скрытое поле плюс кнопки (как было) отвергнуто: без JS кнопки мертвы, а значение не выбрать вовсе.
- Две кнопки отправки со значением (`type` в `name`/`value` submit) отвергнуты: тип нельзя выбрать до заполнения, второй submit ломает единый путь отправки и подсказки.
- Две отдельные формы отвергнуты: удвоение разметки, валидации и тестов, а сервер уже различает тип одним полем.
- Серверное определение типа по заполненным полям отвергнуто: меняет контракт и делает поведение неявным.
- Селект вместо радио отвергнут: хуже видимость двух вариантов и расходится с внешним видом вкладок.

## Последствия

- Две представления одного выбора (радио и вкладки) нужно держать синхронными; клиентский код читает группу как список радио, а не одно значение.
- Без JS на странице видны поля, нужные только для цены, и для «Сотрудничества» они могут сбивать с толку. Сервер их игнорирует.
- Без JS нет подсказки по типу при ошибке полей: HTML-ответ не восстанавливает ввод (ADR 0007).
- Тесты формы обязаны покрывать оба режима, включая `javaScriptEnabled: false` с выбором «Сотрудничество».
