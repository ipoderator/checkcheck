# 0010. Тема: системная по умолчанию, `data-theme` только при ручном выборе, ранний обычный скрипт в `<head>`

## Контекст

Третья задача добавляет тёмную тему (истории 78–79). Страниц пять (`index`, `privacy`, `consent`, `404` и HTML-ответ обработчика заявок), `main.js` подключает только главная и как модуль, то есть после первого кадра. CSP на сайте нет. Тема должна примениться до отрисовки, работать без JS и подхватывать смену системной темы.

## Решение

Без выбора посетителя на `<html>` нет никакого атрибута, тема следует за системой через `prefers-color-scheme`. Когда посетитель нажал переключатель, ставится `data-theme="light|dark"` и выбор запоминается в `localStorage`. Цвета — токены `:root`; тёмные значения лежат в двух местах с одним набором: в медиазапросе (для `:root` без `data-theme="light"`) и в `:root[data-theme="dark"]`. Светлые значения не менялись. Всю логику темы (применение, кнопки, `theme-color`) держит один внешний обычный скрипт в `<head>` без `defer`, общий для всех пяти страниц.

## Почему

- Всегда ставить атрибут (по системной теме при загрузке) отвергнуто: без JS атрибута нет, значит тему пришлось бы дублировать в CSS, и смена системной темы на лету не подхватывалась бы без слушателя. Отсутствие атрибута само означает «следуй системе».
- Класс на `body` отвергнут: `body` в момент работы скрипта из `<head>` ещё не существует, а токены живут на `:root`.
- Применять тему из `main.js` отвергнуто: это модуль, он исполняется после первого кадра, и тёмный посетитель видел бы вспышку светлой темы. Кроме того, `main.js` нет на трёх страницах из пяти.
- Копия inline-скрипта в каждую страницу отвергнута: пять копий, одна из них в PHP-шаблоне; правка логики шла бы в пять мест. CSP нет, но внешний файл не закрывает дверь, если она появится.
- Только CSS без переключателя отвергнут: владелец просил кнопку, а выбор поверх системной темы нужен посетителю, у которого система и вкус расходятся.

## Последствия

- Скрипт в `<head>` без `defer` блокирует разбор страницы одним маленьким запросом; его нельзя «оптимизировать» в `defer`, не вернув вспышку.
- Каждая новая страница сайта обязана подключить этот скрипт и содержать кнопку, иначе она останется на системной теме без переключателя.
- Тёмные значения токенов хранятся в двух местах; правка одного без второго рассинхронизирует «системную» и «выбранную» тёмные темы. Нужен тест на совпадение.
- Любой новый цвет обязан идти через токен: хардкод (их было 33) в тёмной теме читается плохо. Картинки и логотипы с зашитыми цветами проверяются на тёмном фоне отдельно.
- Выбор в приватном режиме не переживёт сессию: ошибки хранилища глотаются, переключатель работает в пределах страницы.
