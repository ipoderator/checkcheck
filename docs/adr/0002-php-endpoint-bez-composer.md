# 0002. Бэкенд заявок — один PHP-эндпоинт на PHP 7.4 без Composer

## Контекст

Заявки должны уходить в Telegram и на e-mail. Хостинг обычный, без Node и без доступа к установке пакетов; локально стоит PHP 8.5, на хостинге может быть 7.4.

## Решение

Бэкенд — один эндпоинт `api/lead.php`, который только вызывает сервис, и небольшая библиотека рядом. Код совместим с PHP 7.4, использует только встроенные возможности (curl или потоки, `mail`, сокеты для SMTP) и не использует Composer.

## Почему

- Отдельный Node-сервис отвергнут: на тарифах Timeweb и Beget его не запустить, а сайт должен работать на любом тарифе.
- Готовые пакеты для почты и Telegram через Composer отвергнуты: на хостинге нет шага установки, а коммитить `vendor/` значит тащить чужой код ради двух простых вызовов.
- Внешний сервис форм отвергнут: заявки с персональными данными ушли бы третьей стороне, а ключи и доступ были бы вне контроля владельца.
- Синтаксис ограничен 7.4, хотя локально PHP новее: иначе тесты проходят там, где хостинг упадёт.

## Последствия

- Нельзя `match`, именованные аргументы, `?->`, `enum`, `readonly`, union-типы, `str_contains` и прочее из PHP 8. Локальный PHP эти ошибки не покажет, только хостинг.
- Свой SMTP-клиент придётся сопровождать самим: STARTTLS, таймауты, особенности Яндекса.
- Расширения кроме стандартных нельзя; для `curl` и `mbstring` нужны запасные пути, то есть два кода на одно действие.
- Тесты бьют по HTTP-контракту, поэтому он стал швом, который трудно менять.
