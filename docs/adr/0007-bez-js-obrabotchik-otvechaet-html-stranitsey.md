# 0007. Без JS обработчик отвечает HTML-страницей, а JS получает JSON

## Контекст

Форма отправляется обычным POST, если скрипт не загрузился или отключён (правило «без JS весь контент виден»). В первой сборке `lead.php` отвечал JSON всегда, и посетитель без JS видел сырой `{"ok":true}` или `{"ok":false,"code":"validation",…}` на пустой странице. Аудит (G25, ист. 63) отметил это как провал для человека. Страницы статические (0001), обработать итог на `index.html` без JS нечем.

## Решение

`lead.php` смотрит на заголовок `Accept`. Если в нём есть `application/json`, ответ — JSON по прежнему контракту (скрипт формы шлёт этот заголовок сам). Иначе ответ — простая HTML-страница в стиле сайта с итогом: «принято», ошибки по полям или «не настроено», со ссылкой «Вернуться к форме». JSON-контракт для JS не меняется, тексты ошибок те же, что в JSON.

## Почему

- Всегда JSON (как было) отвергнуто: форма без JS «работает», но человек видит служебный текст и не понимает, принята ли заявка.
- Обязательный JS (отключить кнопку без скрипта) отвергнут: потерять заявку у посетителя с блокировщиком или старым браузером дороже, чем держать вторую ветку ответа.
- Перенаправление обратно на `index.html` с флагом в адресе отвергнуто: статическая страница без JS не покажет ни итог, ни ошибки полей, а введённое всё равно потеряется.
- Отдельные адреса для JS и для людей отвергнуты: вторая точка входа удвоила бы поверхность спама и тестов (0004), а `Accept` для этого и предназначен.

## Последствия

- Выбор по `Accept` значит, что любой клиент без `application/json` (в том числе `curl` по умолчанию) получает HTML. Тесты контракта обязаны слать нужный заголовок явно, а скрипт формы не должен его терять.
- Появилась ещё одна копия шапки, подвала и стилей — на странице-ответе. Правка реквизитов или телефона касается и её (то же последствие, что в 0001).
- У страницы-ответа три итога, и каждый нужно держать в тестах; новый код ответа сервиса без ветки в HTML превратится в пустой экран.
- Ошибки полей на HTML-странице не восстанавливают ввод: человек возвращается назад кнопкой браузера, и сохранность введённого зависит от браузера. Черновик в `localStorage` без JS не работает.
- Прежняя фраза в `interfaces.md` «без `Accept: application/json` ответ — та же JSON-структура» заменена этим решением.
